# DPopCleaner 0.2.14 R1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build, verify, publish, and link a clean DPopCleaner 0.2.14 R1 installer that contains only the known standalone application executable.

**Architecture:** A policy test treats the installer definition, manifest, site, and GitHub Actions workflow as one release contract. GitHub Actions verifies the standalone EXE hash, optionally signs the staged EXE and installer, builds with Inno Setup, publishes one prerelease asset, writes manifest metadata, and deploys the static site.

**Tech Stack:** PowerShell 7, Inno Setup 6, GitHub Actions, GitHub Releases, static HTML/CSS/JavaScript.

**Spec:** `docs/superpowers/specs/2026-08-22-clean-0.2.14-r1-design.md`

## Global Constraints

- Never publish or copy the old installer with SHA-256 `0b0e7eeec6fe7a28eb046b083700bf7ce94ab4b0ee17bba9ee355203e8c8983e`.
- Accept only `downloads/DPopCleaner_0.2.14_BETA.exe` with SHA-256 `7d5e0a510189db31ef7ee1aca72dc182332a8020d994c81be40a519c5960515c` as the application payload.
- The installer contains one payload file and no WinDivert, winws, Zapret, `.bat`, `.cmd`, or `.ps1` payloads.
- The release tag is `v0.2.14-clean-r1`; the asset is `DPopCleaner_Setup_0.2.14_BETA_CLEAN_R1.exe`.
- No Defender disabling, exclusions, packers, obfuscation, self-signed certificates, or security-warning bypasses.
- The website enables downloads only for a valid available manifest with HTTPS URL, positive size, and 64-hex SHA-256.

### Task 1: Clean installer policy and definition

**Files:**
- Create: `tests/validate-clean-release.ps1`
- Create: `release/DPopCleaner_CLEAN_R1.iss`

**Interfaces:**
- Consumes: `downloads/DPopCleaner_0.2.14_BETA.exe` and its fixed SHA-256.
- Produces: policy test command `pwsh -File tests/validate-clean-release.ps1` and Inno Setup input accepting `/DSourceExe=<path>`.

- [ ] **Step 1: Write the failing policy test**

Create a PowerShell script that asserts the expected source hash, requires `release/DPopCleaner_CLEAN_R1.iss`, counts exactly one active `Source:` entry, requires destination name `DPopCleaner.exe`, and rejects `WinDivert|winws|Zapret|\.bat|\.cmd|\.ps1` in active `[Files]` entries.

```powershell
$ErrorActionPreference = 'Stop'
$root = Split-Path -Parent $PSScriptRoot
$source = Join-Path $root 'downloads/DPopCleaner_0.2.14_BETA.exe'
$expected = '7d5e0a510189db31ef7ee1aca72dc182332a8020d994c81be40a519c5960515c'
if ((Get-FileHash -Algorithm SHA256 $source).Hash.ToLowerInvariant() -ne $expected) { throw 'Unexpected standalone EXE hash.' }
$issPath = Join-Path $root 'release/DPopCleaner_CLEAN_R1.iss'
if (-not (Test-Path $issPath)) { throw 'Missing clean R1 installer definition.' }
$activeSources = Get-Content $issPath | Where-Object { $_ -match '^\s*Source\s*:' }
if ($activeSources.Count -ne 1) { throw "Expected one installer payload, found $($activeSources.Count)." }
if ($activeSources[0] -notmatch 'DestName:\s*"DPopCleaner\.exe"') { throw 'Payload destination must be DPopCleaner.exe.' }
if ($activeSources[0] -match 'WinDivert|winws|Zapret|\.bat|\.cmd|\.ps1') { throw 'Forbidden payload in installer.' }
```
