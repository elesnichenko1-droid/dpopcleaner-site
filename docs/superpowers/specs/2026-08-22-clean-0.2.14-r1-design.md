# DPopCleaner 0.2.14 R1: чистая сборка и публикация

## Цель

Опубликовать на сайте рабочий установщик DPopCleaner 0.2.14 R1, который не содержит набора дополнительных Zapret/WinDivert-скриптов из старого установщика, вызвавшего срабатывание `Trojan:Win32/Wacatac.C!ml`.

Нельзя обещать отсутствие любых будущих предупреждений SmartScreen: оно зависит от цифровой подписи и репутации файла. Публикация должна исключить известный заблокированный установщик и дать пользователю проверяемые SHA-256, размер и сведения о подписи.

## Проверенные исходные артефакты

- Старый заблокированный установщик: `DPopCleaner_Setup_0.2.14_BETA.exe`, 4 506 112 байт, SHA-256 `0b0e7eeec6fe7a28eb046b083700bf7ce94ab4b0ee17bba9ee355203e8c8983e`. Он не используется и не публикуется.
- Автономное приложение: `downloads/DPopCleaner_0.2.14_BETA.exe`, 389 632 байта, SHA-256 `7d5e0a510189db31ef7ee1aca72dc182332a8020d994c81be40a519c5960515c`. Обе копии в `downloads/` идентичны. Этот файл служит единственным содержимым новой установки.
- Оба артефакта не имеют Authenticode-подписи.

## Архитектура релиза

1. Новый workflow располагается в `.github/workflows/build-clean-0.2.14-r1.yml` и запускается вручную.
2. Workflow сверяет SHA-256 автономного EXE до любых действий. Несовпадение останавливает выпуск.
3. Inno Setup создаёт `DPopCleaner_Setup_0.2.14_BETA_CLEAN_R1.exe`. Установщик содержит только `DPopCleaner.exe`, ярлыки и запись удаления приложения. Он не содержит `WinDivert`, `winws`, Zapret, PowerShell- или batch-файлы.
4. Если настроены секреты `WINDOWS_CERT_PFX_BASE64` и `WINDOWS_CERT_PASSWORD`, workflow подписывает копию приложения и готовый установщик SHA-256-подписью с RFC 3161 timestamp. Исходный файл в репозитории не меняется.
5. Workflow вычисляет SHA-256 и размер готового установщика и проверяет его цифровую подпись, если подписание было включено.
6. Релиз публикуется как prerelease с тегом `v0.2.14-clean-r1`. Повторный запуск заменяет только asset этого тега.
7. `update/beta.json` указывает на точный asset, содержит версию `0.2.14`, ревизию `1`, SHA-256, размер, `signed` и `available`.
8. GitHub Pages публикует только веб-файлы и manifest. Кнопки сайта читают URL из `update/beta.json`; прямого запасного URL на старый установщик нет.

## Защитные ограничения

- Старый установщик с хешем `0b0e...8983e` никогда не копируется в workflow, release или Pages.
- Сборка прекращается, если Inno-скрипт содержит дополнительные payload-файлы или имена `WinDivert`, `winws`, Zapret, `.bat`, `.cmd`, `.ps1`.
- Сборка прекращается, если manifest указывает не на HTTPS GitHub Release или на другое имя файла.
- Публикация не отключает Defender, не создаёт исключения и не использует упаковщики/обфускацию.
- При отсутствии сертификата сайт честно показывает, что сборка не подписана. Подпись не подменяется самоподписанным сертификатом.

## Изменения сайта

- Все пользовательские упоминания релиза остаются `0.2.14 BETA`; техническая ревизия отображается как `R1` в статусе релиза.
- Размер и хеш берутся только из manifest.
- Кнопка скачивания активируется только при `available: true`, валидном HTTPS URL, положительном размере и 64-символьном SHA-256.
- В блоке безопасности добавляется явная информация: чистый установщик содержит только DPopCleaner и не включает Zapret/WinDivert-компоненты.

## Проверка

До публикации:

- тест политики Inno Setup подтверждает единственный payload;
- тест manifest подтверждает версию, ревизию, URL, размер и SHA-256;
- проверяется идентичность исходного standalone EXE ожидаемому хешу;
- локальные веб-тесты подтверждают выключенную кнопку при неверном manifest и рабочую кнопку при валидном manifest;
- workflow выполняет сборку на `windows-2022` и публикует prerelease только после всех проверок.

После публикации:

- проверить успешность build и Pages workflow;
- скачать asset по публичному URL и повторно сверить размер и SHA-256;
- проверить, что URL сайта ведёт именно на `v0.2.14-clean-r1`;
- проверить файл локальным Defender до объявления релиза готовым;
- если Defender снова обнаружит угрозу, снять `available`, не распространять asset и отправить файл Microsoft как возможное ложное срабатывание.

## Откат

При любой проблеме `available` возвращается в `false`, кнопка сайта отключается, а prerelease остаётся недоступным с главной страницы для последующего анализа. Старый заблокированный установщик не восстанавливается.
