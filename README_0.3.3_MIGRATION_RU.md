# DPopCleaner 0.3.3 — обратная миграция на UX 0.2.14

## Что именно делается

Цель этой ветки — не продолжать заменять хороший интерфейс 0.2.14 новым shell'ом 0.3.2. Вместо этого 0.3.3 собирается по обратной схеме:

**UX/поведение 0.2.14 → восстановленная база → функции/ядро 0.3.2 → DPopCleaner 0.3.3 BETA R1.**

В репозитории оригинальный исходный C++ код точного бинарника 0.2.14 не сохранился. Сохранился автономный нативный EXE и сопровождаемая реконструкция, а также специальный embedded recovery-payload с назначением `restore faithful DPopCleaner 0.2.14 UX on 0.3.2 core`. Поэтому мигратор использует именно этот recovery как источник восстановленного интерфейса, а не пытается модифицировать готовый EXE.

## Защита старых версий

Мигратор не работает непосредственно в текущем checkout. Он создаёт detached Git worktree во временной директории, применяет recovery только там, копирует восстановленный `v032` в новый `v033`, после чего меняет версию на 0.3.3.

Recovery-payload имеет жёсткую границу: разрешены только пути `v032/` и `scripts/`. `r4/`, `downloads/`, `update/`, сайт и корневые файлы публикации через payload изменить нельзя.

## Что переносится в 0.3.3

- восстановленный 0.2.14-style shell/UX из faithful recovery;
- 0.3.2 core и FullCore;
- системная очистка и диагностика, уже входящие в recovered 0.3.2 overlay;
- тесты shell/layout/theme/controls/session/status/overview/fullcore;
- существующие базовые модули Cleaner, StartupManager, DPopGuard, ZapretManager, Applications и updater через нормализованную R3 source-map базу;
- версия приложения и Windows resources меняются на `0.3.3 BETA R1` / `0.3.3.1`.

## Проверки

До Windows-сборки запускаются Python-тесты самого мигратора. Они проверяют:

- корректное извлечение gzip+base64 recovery;
- отказ при битом payload;
- запрет абсолютных путей и `..`;
- запрет изменений вне `v032/` и `scripts/`;
- отсутствие частичной записи при ошибке версии;
- точный version bump 0.3.2 → 0.3.3;
- работу в detached worktree без изменения исходного `v032`;
- экспорт отдельного `v033`.

На Windows затем выполняются CMake Release build и CTest. GitHub workflow дополнительно запускает полученный `DPopCleaner.exe`, ждёт появления главного окна и проверяет корректное закрытие.

## One-click в GitHub Actions

После добавления файлов из этого пакета в репозиторий используется workflow:

`.github/workflows/DPopCleaner_0.3.3_REVERSE_MIGRATION.yml`

Он ничего не публикует на сайт и не заменяет текущий release. Результат появляется только как Actions artifact `dpopcleaner-0.3.3-reverse-migration`, пока сборка не будет отдельно проверена.

## Локальный запуск на Windows

Из корня репозитория:

```powershell
.\RUN_DPopCleaner_0.3.3_MIGRATION.ps1
```

Нужны Python 3, Git, CMake и Visual Studio 2022 C++ Build Tools. Результаты появляются в `dpop033-output`.

## Критерий готовности первой сборки 0.3.3

Первая техническая сборка считается успешной только если одновременно:

1. Python migration tests проходят полностью.
2. Recovery применяется в изолированном worktree.
3. `v033` имеет версию `0.3.3 BETA R1` во всех целевых version-файлах.
4. Visual Studio Release build завершён успешно.
5. CTest завершён без падений.
6. `DPopCleaner.exe` открывает главное окно и корректно закрывается.
7. В `migration-report.json` записаны SHA-256 итоговых EXE.

Публикация сайта/manifest намеренно отделена от этого шага: сначала проверяем саму 0.3.3.
